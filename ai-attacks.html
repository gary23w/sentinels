NAME

sentinels-ai - how garrett spots and ends an intrusion that an AI agent runs

DESCRIPTION

An AI agent that breaks into a machine still has to get in and still has to run commands once it is there. It may get in through something that faces the network, such as a web application, or through a document or an email someone opens. Then it starts working.

What gives it away is how it works. It runs commands faster than a person types, it retries a failed step with a small change, and its sub-agents repeat each other. garrett knows these marks. When commands start at machine pace where an intruder lands, its default mode ends the program on the machine itself, without asking a model.

THE MARKS IT LOOKS FOR

garrett counts them among the commands one program starts within three minutes. Each one comes with a reason in plain words, quoted here as the agent writes it (N and S are the counts it fills in):

a command stream
Six or more different commands started one after another under the same program.
"N different commands were started one after another in S seconds under the same program, the pace of an automated operator."
retries with small changes
Three or more commands that are each a near-copy of the command just before them.
"N commands in a row were near-copies of the one before, the way an automated operator retries a failed step with a small change."
parallel sub-agents
The same command started again within three seconds, more than once, in the middle of varied work.
"The same command was started more than once at the same moment N time(s), the way parallel sub-agents repeat each other."

These marks only count where an intruder lands: under a web server or another program that accepts network connections, or in a shell or script that a document, browser or mail program started. Commands you type yourself in a terminal or over SSH are not judged this way.

A program outside the system folders that calls an AI model's API adds one point of evidence. That alone is never acted on.

WHAT IT DOES ABOUT THEM

Some combinations have almost no honest use, so garrett acts on them at once instead of waiting for more evidence. These are among them, in the agent's own words:

  • a web server started a shell that is exploring the machine
  • a web server started a shell with a download-and-run or reverse-shell command
  • a web server is running a stream of commands at machine pace
  • a document or mail program is running a stream of commands at machine pace

An intruder's very first check of who it is and what the machine is counts as exploring. When a web server started that shell, garrett does not need to see the stream that would follow.

In the default kill mode it ends the program and everything it started, at once, and the default mode does not call a model to do it. Then it cleans up: a dropped file goes to quarantine, and a cron job, Run key or service that would bring it back is switched off.

You choose how hard it hits. pause freezes the program and waits for you, decide freezes it and lets your own service's model decide, and report only tells you.

QUESTIONS

Does it need a cloud account?

No. Installed by itself, garrett protects the machine it is on and keeps its cases there. To see several machines in one place, you run the Sentinel service on your own hardware, and the cases stay on it.

Does kill mode use AI?

No. The default kill mode decides on the machine and does not call a model. A model is used only if you configure a provider on your service, for case write-ups and for decide mode.

What happens when it gets it wrong?

garrett restore <case> puts back everything it cleaned up: quarantined files and switched-off startup entries. garrett trust <case> tells it the program is yours. If you would rather watch first, install it in report mode and read the cases for a week.

Which systems does it run on?

Linux (x86_64, ARM64 and ARMv7), macOS and Windows. Debian and Ubuntu can also install it from the project's signed apt repository.

What does it cost?

Nothing. The agent and the service are open source under the MIT license. If you would rather not run the service yourself, it can be hosted for you.

INSTALLATION

Linux and macOS:

curl -fsSL https://gary23w.github.io/sentinels/install.sh | sudo sh

Windows, from an elevated PowerShell:

irm https://gary23w.github.io/sentinels/install.ps1 | iex

To start with reports only:

curl -fsSL https://gary23w.github.io/sentinels/install.sh | sudo sh -s -- --mode report
